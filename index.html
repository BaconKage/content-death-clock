Idea What "attention death" means

Watch a video die

We measure a video's speed: views gained per hour between two readings, as a share of its own best hour. Once its speed drops below 5% of its best and stays there for two readings, we call it dead. Comparing each video with its own peak is what makes a tiny channel and a huge one comparable. Press play, or drag the slider.

Big Data How the data was collected

A collector that never sleeps

Nobody can download this data: a video's first hours happen once, and if nobody is watching, they are gone. So we built a pipeline that runs on GitHub's servers every 30 minutes, for weeks, with no one at a keyboard. It asks YouTube which of — channels posted something new and re-measures every video that is due a reading.

From the API to the answer

Raw files (bronze)Every answer saved exactly as it came, one file per run, never edited. Committed to the public repo by the collector itself.
Clean tables (silver)Duplicates removed, ages recomputed from real timestamps, hidden counts kept as missing rather than zero.
Analysis set (gold)One row per video: what was visible at hour 7, and when it actually died.
ModelsSurvival models scored against simple baselines, never trained and tested on the same channel.

Research How we tested it

Rules first, results second

Before a single video had died, we wrote down exactly what we would test, how, and what would count as success, and committed it to a public repository with a date on it. Every later change was added as a dated note with its reason. Then we kept a set of newer videos sealed, to be tested once, at the end.

Research What we found

Better than guessing, but not by much

Our best model picks the video that dies first — of the time on the main set, against 50% for a coin flip. But knowing only the channel's size gets you most of that. And for the exact time, nothing we built beats simply saying "about four days" for every video.

So what What it means

A modest answer you can trust

It is predictable, a little

On two separate sets of videos, a model ranks which dies first about 60% of the time. That held up when we checked it on data it had never seen.

Exact timing is out of reach

Every method is off by about a factor of two. A single number, the average lifetime, does as well as any model on "when exactly".

"It's all about the channel" was wrong

The main set suggested channel size explains almost everything. The sealed test disagreed, so we withdrew that claim instead of keeping the convenient story.

The method is the contribution

A frozen plan, a sealed test opened once, every change dated, every failure written down. That is what makes a negative or modest result worth reading.
